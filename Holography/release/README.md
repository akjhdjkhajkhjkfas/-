# 40 行 × 64 列阵面控制程序

双击本目录中的 `Holography40x64.exe` 启动。程序使用 Windows 自带的 .NET Framework 4.x；不需要 Python 或 Qt。已加入 TCP 连接和阵面数据发送。原始 Qt release 文件和 MATLAB 程序未改动。

## 向阵面发送

1. 设备 IP 默认为 `192.168.1.10`，TCP 端口默认为用户确认的 `5001`。电脑网卡沿用已测试成功的配置及网关 `192.168.1.1`，程序不修改网络设置。
2. 点击“连接设备”，操作记录显示“连接成功”后，导入 40 行 × 64 列的实际码本。
3. 检查预览，点击“执行：发送当前码本”。程序发送点击时的网格快照，编辑后的数据也会包含在发送包中。导入、连接或发送进行时，相关按钮暂时禁用，避免操作冲突。
4. 默认等待设备的 ASCII `OK` 或 `ERROR` 回执，支持回执分段到达。收到 `OK` 才记录“执行成功”；`ERROR` 记录为设备拒绝数据。5 秒没有回执会记录“执行结果未确认”并关闭连接，不自动重发。
5. 如果实际固件不提供这些回执，可取消“等待设备 OK / ERROR 回执”；此时只记录已提交发送，不能从软件判定阵面是否执行。切换回执模式时会断开连接，需要重新连接，以免将之前残留的回执误认为新回执。
6. 点击“断开连接”关闭 TCP 连接。未连接或尚未导入、编辑、清零生成码本时，发送按钮不可用。

## 已确认的发送格式

用户确认新控制板的接收规则如下：

- 从第 1 行到第 40 行逐行发送；每行从第 1 列到第 64 列。
- 每 8 个二值单元合成 1 字节，左侧单元对应高位；第 1 列对应首字节 bit7，第 8 列对应 bit0。
- 每行 8 字节，一包共 320 字节原始二进制数据。
- 不添加包头、包尾、长度字段、校验和或换行，也不发送 ASCII 形式的 0/1 或十六进制字符。
- “导出发送包 BIN”产生与点击执行时同样的 320 字节数据，可用网络调试助手按二进制文件发送进行对照。

例如第 1 行第 1、8 列为 1，则首字节为 `81`；第 2 行第 1 列为 1，则第 9 字节为 `80`；第 40 行第 64 列为 1，则最后一个字节为 `01`。这里的数字是十六进制字节值。

- 固定显示 40 行、64 列，共 2560 个单元；左上角为第 1 行第 1 列。
- 橙色表示 1，白色表示 0。窗口缩放时保持单元格为正方形。
- 导入支持 XLS、XLSX、CSV、TSV；Excel 文件使用首个工作表的 UsedRange，需要安装 Microsoft Excel，与原程序的读取方式一致。CSV 不需要 Excel。
- 文件必须恰好为 40 行、64 列，内容仅允许 0/1，不含标题。尺寸错误、空单元格、非二值内容会拒绝导入，并保留当前预览。
- 勾选“允许点击网格修改 0 / 1”后可以编辑；“导出 CSV”保存当前数据。
- “加载演示图案”仅用于检查显示，不是计算得到的天线码本。
- 原 CodeBook 中的 72 行 × 32 列文件不能直接导入为新尺寸；程序不会擅自裁剪、补零或重新排列。

## 构建与验证

在 PowerShell 中运行 `./build.ps1` 重新构建。界面、导入和编辑源码为 `Preview.cs`；打包与通信源码为 `Transport.cs`。

运行 `./Holography40x64.exe --self-test <输出目录>`，执行 CSV 往返、无效输入校验、三种窗口尺寸布局检查、2560 个单元中心像素检查，以及界面连接/发送/断开按钮的本机 TCP 端到端测试。`../verification` 保存本次测试结果与预览图。`TestExcel.cs` 单独验证 XLS/XLSX 导入及旧尺寸拒绝行为。

`TestTransport.cs` 和 `TestTransport.exe` 验证逐个单元的全部 2560 种单点开启数据、320 字节长度、全零/全一及已知字节向量，并使用本机 TCP 模拟设备验证两次连续发送、分片 OK/ERROR 回执、超时、并发发送拒绝、断线、无回执模式、未知回执及重连。此次测试没有向实际阵面发送数据，实板执行结果以设备回执和实际阵面表现为准。

## 逆向分析依据

分析对象为现有 `release/mainwindow.o`、`excel.o` 及 `moc_mainwindow.cpp`，使用 `nm -C` 和 `objdump -dr -C` 读取符号和反汇编。

1. `MainWindow::DataInit`（.text 偏移 0xa50）创建 QGraphicsScene。横坐标从 372 以 12 递减至 0，共 32 列；纵坐标从 710 以 10 递减至 0，共 72 行。因此旧网格尺寸是代码硬编码。
2. `Excel::ExcelRead` 使用 Excel.Application → Workbooks.Open → Sheets.Item → UsedRange.Value。
3. `MainWindow::on_RunBtu_clicked`（0x1150）在连接成功时调用 QIODevice::write，直接发送已经转换的 QByteArray。
4. `MainWindow::DataTrans`（0x2cf0）引用 UnitIndex、SinIndex、DataIndex 三组映射，并将每组 8 个值移位组合成一个字节。末尾循环为 24 × 12 字节，即固定 288 字节，而非简单按 Excel 行连续发送。
5. `MainWindow::readData`（0x1260）识别 ASCII `OK` 和 `ERROR`。常量区给出的默认设备地址为 192.168.1.10:7。

旧 Qt 程序使用 72×32 通道映射和固定 288 字节包。新程序按用户随后明确确认的 40×64 逐行、高位在前接收规则生成 320 字节包，使用用户确认的 TCP 5001 端口，不套用旧阵面的通道映射。

若后续同步改 MATLAB 码本，按当前双极化交错、最后转置导出的逻辑，40 行 × 64 列对应 `numberX=32`、`numberY=40`。这次没有修改 MATLAB 参数，也没有把演示图案当作实际阵面码本。
